title: "Storage Adapters"
description: "Persist and synchronize quota counts using Memory or Redis adapters."
---

## Available Adapters

The `ZeroTrustBalancer` tracks daily usage counts for each connected sending server. You can choose between two built-in adapters or implement your own custom adapter using the `StorageAdapter` interface.

---

## 1. MemoryStorageAdapter

The default in-memory adapter. Best for standalone Node.js servers, CLI tools, or automated test suites.

```typescript
import { ZeroTrustBalancer, MemoryStorageAdapter } from "@emailconnector/sdk";

const balancer = new ZeroTrustBalancer({
  storage: new MemoryStorageAdapter(),
  servers: [ /* ... */ ],
});
```

<Warning>
`MemoryStorageAdapter` stores counters in process RAM. If your application runs in an auto-scaling serverless environment (e.g. AWS Lambda or Vercel Edge), use `RedisStorageAdapter` to avoid quota fragmentation.
</Warning>

---

## 2. RedisStorageAdapter

The multi-instance production adapter. Uses atomic Redis increments (`INCR` with 24-hour TTL) to keep daily counters perfectly synchronized across any number of containers, serverless instances, or edge nodes.

```typescript
import { ZeroTrustBalancer, RedisStorageAdapter } from "@emailconnector/sdk";
import Redis from "ioredis";

const redisClient = new Redis(process.env.REDIS_URL!);

const balancer = new ZeroTrustBalancer({
  storage: new RedisStorageAdapter(redisClient, {
    keyPrefix: "ec:quota:", // Defaults to "ec:quota:"
  }),
  servers: [ /* ... */ ],
});
```

---

## Custom Storage Adapter Interface

You can implement your own adapter (e.g. MongoDB, PostgreSQL, DynamoDB) by implementing the `StorageAdapter` interface:

```typescript
export interface StorageAdapter {
  getUsage(serverId: string): Promise<ServerUsage>;
  incrementUsage(serverId: string, count?: number): Promise<ServerUsage>;
  resetUsage(serverId: string): Promise<void>;
}
```
